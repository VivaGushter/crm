# Master CRM v2.1

Master CRM — внутренняя CRM-система для управления заявками выездных мастеров с календарём выездов, прайс-листом, калькуляцией услуг, клиентской базой, аналитикой и Telegram-интеграцией.

## Возможности

### Заявки
- Создание, просмотр, редактирование и удаление заявок с учётом роли и серверных разрешений
- Поля: клиент, дата и время выезда, адрес, телефон, источник, способ связи, статус, цена, ответственный и комментарий
- Статусы: Новая, Назначена, В работе, Завершена, Отменена
- Фильтры по статусу, мастеру, дате, источнику и способу связи
- Поиск по клиенту, адресу, телефону, комментарию и ответственному
- **Калькуляция / Состав работ**: добавление позиций из прайса с количеством и ценой
- **Детальный просмотр**: модальное окно с полной информацией о заявке и составом работ
- Адреса открываются в Google Картах из списка заявок, календаря, истории клиента и окна просмотра

### Калькуляция
- Отдельная страница `/calculation` для выбора позиций прайса
- Поиск и фильтрация по категориям
- Корзина выбранных позиций с изменением количества
- Итоговая сумма
- Быстрый переход к созданию заявки с переносом состава работ
- Интеграция с формой заявки: редактирование количества и цены на месте
- Поддержка текстовых цен, например `от 500`

### Календарь
- Представления: Месяц, Неделя и День
- Цветовые маркеры статусов заявок
- Синхронизация выбранного дня с фильтром и списком заявок
- Локальная дата формируется без UTC-сдвига
- Исправлены переключение дней и недель и время по умолчанию для новой заявки

### Прайс-лист
- Отдельная страница `/price` с категориями услуг и позициями
- Создание, редактирование и удаление категорий и позиций
- Поля позиции: название, цена, единица измерения и порядок отображения
- Обычные цены, диапазоны и текстовые значения: `1500`, `1500-4000`, `от 500`
- Категории сворачиваются; при открытии страницы они закрыты по умолчанию
- Адаптивное отображение на смартфоне
- CSV-экспорт с корректным экранированием значений
- Администратор может редактировать прайс; менеджер — только при наличии серверного разрешения `can_edit_price`

## Роли и права доступа

| Роль | Возможности |
|---|---|
| Мастер | Видит только назначенные ему заявки и календарь; не имеет доступа к общей клиентской базе, аналитике и отчётам; не может создавать заявки на других мастеров или переназначать заявки другим мастерам |
| Менеджер | Управляет заявками и доступными разделами в пределах выданных серверных разрешений |
| Администратор | Полный доступ, включая пользователей, разрешения, настройки и прайс |

Для менеджеров сервером учитываются отдельные разрешения на:
- редактирование прайса;
- изменение заявок;
- удаление заявок.

Добавлен API для сохранения разрешений менеджера. Кнопки действий во frontend также учитывают права текущего пользователя, однако источником истины остаются серверные проверки.

## Пользователи и авторизация

- Веб-интерфейс использует сессионную авторизацию с Bearer-токенами
- Исправлена работа флажка «Запомнить меня»
- Новые пароли хешируются через **scrypt** с индивидуальной солью
- Старые SHA-256-хеши автоматически обновляются до нового формата после успешного входа
- При смене пароля или роли пользователя отзываются его веб-сессии и Telegram-привязки
- Нельзя снять роль администратора с текущего администратора или последнего оставшегося администратора
- Исправлена блокировка SQLite при удалении пользователя
- Добавлена команда для создания первого администратора
- Исправлены создание пользователя после редактирования и сохранение пользователя без смены пароля

## Клиенты, аналитика и аудит

- База клиентов формируется на основе заявок и содержит историю обращений
- Экспорт клиентов в CSV с корректным экранированием
- Статистика по заявкам, статусам, источникам и выручке
- Рейтинг мастеров и активных клиентов
- Отчёты за произвольный период
- Мастера не имеют доступа к общей клиентской базе, аналитике и отчётам
- Изменение заявки и соответствующая запись аудита сохраняются в одной транзакции
- Аудит охватывает операции с заявками, прайсом и разрешениями пользователей

## База данных и валидация

Приложение использует SQLite. Таблицы и миграции создаются при запуске через `backend/db.py`.

- Путь к БД можно переопределить переменной окружения `CRM_DB_PATH`
- Добавлены индексы для заявок, сессий и состава работ
- Добавлена проверка корректности дат
- Числовые значения проверяются на конечность (`NaN` и бесконечность не принимаются)
- Миграции проверены на копии существующей БД: записи сохранены, нарушений целостности не обнаружено

Основные сущности: пользователи, сессии, заявки, категории прайса, позиции прайса, состав работ заявок (`request_items`) и аудит-лог.

## Быстрый запуск

### Требования
- Python 3.10+
- SQLite3
- Git
- Nginx и systemd — для production-развёртывания

```bash
cd /opt
git clone https://github.com/VivaGushter/crm.git master-crm
cd master-crm
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
python app.py
```

Альтернативный запуск:

```bash
uvicorn app:app --host 0.0.0.0 --port 8000
```

При необходимости укажите другой путь к базе данных:

```bash
export CRM_DB_PATH=/path/to/crm.db
python app.py
```

## Первый администратор

В проект добавлена команда создания первого администратора. Используйте её при первоначальном развёртывании в соответствии с актуальной CLI-командой приложения.

## systemd и Nginx

Пример systemd-сервиса обновлён и находится в `master-crm.service`.

```bash
sudo cp master-crm.service /etc/systemd/system/master-crm.service
sudo systemctl daemon-reload
sudo systemctl enable master-crm
sudo systemctl start master-crm
sudo systemctl status master-crm
```

Логи приложения:

```bash
sudo journalctl -u master-crm -f
```

Nginx:

```bash
sudo cp nginx-master-crm.conf /etc/nginx/sites-available/master-crm
sudo ln -s /etc/nginx/sites-available/master-crm /etc/nginx/sites-enabled/master-crm
sudo nginx -t
sudo systemctl reload nginx
```

## Telegram-бот

`telegram_bot.py` сохранён в проекте, но бот в настоящее время не используется и дальнейшая доработка после этого уточнения не выполнялась.

До приостановки работ по боту:
- удалён встроенный токен;
- добавлены проверки доступа;
- добавлено сохранение изменения статуса заявки.

**Важно:** старый Telegram Bot Token автоматически не отзывался. Если он ранее находился в репозитории, его следует считать скомпрометированным и вручную перевыпустить через BotFather.

При возобновлении использования бота токен должен храниться вне репозитория, например в переменной окружения.

## API

После входа защищённые API-запросы используют сессионный Bearer-токен. Сервер самостоятельно проверяет роль и разрешения пользователя; ограничения интерфейса не заменяют серверную авторизацию.

Основные группы API:

| Группа | Назначение |
|---|---|
| `/api/auth/*` | Вход, выход, текущая сессия и авторизация |
| `/api/requests*` | Список, создание, просмотр, изменение и удаление заявок |
| `/api/users*` | Пользователи, роли и разрешения |
| `/api/prices*` | Категории, позиции и экспорт прайса |
| `/api/report*` | Отчёты за период |
| `/api/admin/*` | Клиенты, аналитика и аудит |
| `/api/settings*` | Пользовательские настройки |

## Резервные копии

Перед обновлением production-сервера создавайте резервную копию БД:

```bash
cd /opt/master-crm
cp data/crm.db "data/crm.db.backup-$(date +%F-%H%M%S)"
```

Если используется `CRM_DB_PATH`, резервную копию нужно создавать по фактическому пути к БД.

## Безопасность

- Защищённые API используют сессионные Bearer-токены
- Проверки ролей и разрешений выполняются на стороне API
- Мастера ограничены назначенными им заявками
- Новые пароли хешируются через scrypt с индивидуальной солью
- Старые SHA-256-хеши мигрируют после успешной авторизации
- Критичные изменения данных и аудит выполняются транзакционно
- При смене пароля или роли активные сессии и Telegram-привязки пользователя отзываются
- Не храните пароли, токены и секреты в Git
- Используйте HTTPS, уникальные пароли и регулярные резервные копии
- Старый Telegram Bot Token необходимо вручную отозвать, если это ещё не сделано
